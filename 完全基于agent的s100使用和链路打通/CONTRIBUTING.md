# 贡献指南

这个仓库记录 S100P 从烧录、联网、RDK Studio 接入到使用 agent 跑通 YOLO 的可复现流程。贡献内容应优先提升可操作性，而不是增加泛泛介绍。

## 可以贡献什么

- 新板卡或新系统版本的实测记录。
- 某一步失败后的可复现修复方法。
- 更稳健的脚本和检查命令。
- RDK Studio、TROS、hobot_dnn、YOLO 示例的版本差异说明。
- 新的 agent skill，但需要说明触发条件、输入、输出和成功判据。

## 提交问题时请提供

- 板卡型号和系统镜像版本。
- 主机系统，例如 Windows 11 或 Ubuntu 22.04。
- 连接方式，例如右侧 `eth1` 网口直连、路由器接入或 USB 串口。
- 板端 IP、用户名可以提供；不要提交真实密码。
- 执行到哪一步失败。
- 关键命令输出或截图。
- 如果是 YOLO 问题，请提供输入图片路径、输出图片路径、运行日志和 ROS2 topic 检查结果。

## 提交 PR 时请检查

- 文档里的命令标明是在电脑端还是 S100P 板端执行。
- 不把个人密码、私有 IP 之外的敏感信息写入仓库。
- 默认值使用 `<BOARD_IP>`、`<BOARD_USER>`、`<YOLO_WORKDIR>` 这类占位符。
- 新脚本在失败时返回非零退出码。
- 涉及板端运行的脚本给出成功判据，例如生成结果图、HTTP 可访问或 ROS2 topic 有输出。
- 更新了相关 skill，使 agent 能按新流程执行。

## 文档风格

- 优先写实测路径，再补充可选路径。
- 遇到官方文档容易误导的地方，明确写出实测结论和原因。
- 命令块前说明执行位置。
- 排错内容按“现象、可能原因、检查命令、修复方式”组织。
