# Stability Snapshot Runbook

This runbook supports A-010: 7x24 stability testing.

## Goal

Create a repeatable point-in-time stability snapshot before enabling a long-running 7-day test.

The first probe records:

- Uptime and boot time.
- Load average.
- Memory and swap.
- Disk usage for root, OpenClaw workspace, and NAS path if present.
- OpenClaw config validation.
- OpenClaw Gateway process/listener state.
- Recent Gateway error-like logs.
- Recent kernel OOM-like logs.

## Entry Point

Use the allowlist runner:

```bash
scripts/run_allowlisted_tool.sh stability_snapshot_probe [output_dir]
```

Default local fallback output:

```text
/root/.openclaw/workspace/logs/probes
```

NAS-backed output after A-003 is complete:

```text
/mnt/nas/openclaw/logs/probes
```

## Scheduled Sampler

After the point-in-time probe is validated, install the low-frequency systemd
timer:

```bash
scripts/install_stability_sampler.sh plan
scripts/install_stability_sampler.sh install
```

Default behavior:

- Runs `stability_snapshot_probe.sh` every 30 minutes.
- Writes reports to `/root/.openclaw/workspace/logs/probes`.
- Starts one immediate sample after installation.
- Uses a systemd oneshot service plus timer:
  - `openclaw-stability-sampler.service`
  - `openclaw-stability-sampler.timer`

Use NAS output after A-003 is mounted:

```bash
scripts/install_stability_sampler.sh install /mnt/nas/openclaw/logs/probes
```

Check current timer state:

```bash
scripts/install_stability_sampler.sh status
```

Summarize collected snapshots:

```bash
scripts/run_allowlisted_tool.sh stability_summary_probe \
  /root/.openclaw/workspace/logs/probes \
  /root/.openclaw/workspace/reports/stability
```

Uninstall the sampler:

```bash
scripts/install_stability_sampler.sh uninstall
```

The sampler installer is not exposed through the OpenClaw conversation tool
allowlist. Installing or removing a systemd timer is an operator action; the
OpenClaw tool remains limited to read-only snapshots.

## OpenClaw Tool

The narrow OpenClaw plugin exposes the same workflow through:

```text
s100p_run_probe
```

with:

```json
{"tool_id":"stability_snapshot_probe"}
```

## Acceptance

Local snapshot readiness is verified when:

- The runner writes `stability_snapshot_*.md`.
- The OpenClaw agent can call `s100p_run_probe` with `tool_id=stability_snapshot_probe`.
- The summary reports Gateway status, NAS mount status, reboot records, OOM matches, and Gateway error-like matches.

A-010 is not fully verified until the snapshot runs on a schedule for 7 days and the generated reports are summarized.

The summary report is generated by:

```text
scripts/probes/stability_summary_probe.sh
```

It aggregates `stability_snapshot_*.md` files and reports:

- Snapshot count.
- First and last sample times.
- Elapsed hours.
- Maximum observed reboot records.
- Maximum observed kernel OOM matches.
- Maximum observed Gateway error-like log matches.
- Observed Gateway and NAS status values.

Scheduled-sampler readiness is verified when:

- `openclaw-stability-sampler.timer` is active.
- `openclaw-stability-sampler.service` has completed at least one sample.
- At least one new `stability_snapshot_*.md` report is generated after timer installation.

A-010 7x24 acceptance still requires a 7-day sample set and a summary of reboot,
OOM, Gateway error, disk, and memory trends.
