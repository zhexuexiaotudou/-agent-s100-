`reports/020_s100p_dump_logits_run.json` ran `10` probe cases. All `10` cases are listed as blocking anomalies. The final BPU top-5 logits are all `0.0`, with top token selected by tie behavior. This supports “uniform/constant final logits” as a deployment blocker, not as a semantic token claim.

### 3. Dequant audit

`reports/060_dequant_audit.json` reports:

- verdict: `upstream_graph_or_runtime_issue_raw_constant`
- raw constant cases: `10` / `10`
- final output scale: `0.00025415877462364733`

Because raw output is already all-zero/constant across the full-chain BPU dump, alternate dequant formulas cannot recover useful logits. This shifts suspicion upstream of final dequant: graph execution, runtime output production, final-segment input contract, or final-segment behavior on real chain hidden states.

### 4. Final segment `seg27_28` / `lm_head q16`

`reports/040_final_segment_lmheadq16_audit.json` contains the most useful new localization signal:

- Synthetic hidden inputs produce **nonconstant** logits and top-1 changes with input.
- `real_bpu_seg26_output` produces **all-zero** raw/dequant logits.

The next target is the contract between `seg26_27` output and `seg27_28` input: layout, dtype, quantization, expected range, scale, position id handling, and runtime input interpretation.

## Claims that are safe for paper/report

Safe claim:

> Dream7B seq128 B=1 segmented HBM with lm_head q16 last-token logits passed compile feasibility and S100P load/run/shape checks. However, the tested BPU logits path is blocked against the available GGUF Q4_K_M deployment reference, and BF16/PyTorch ground truth is unresolved. Current evidence localizes the anomaly to the real segmented chain output path around `seg26_27 -> seg27_28` or final-segment input/runtime interpretation, because isolated `seg27_28` responds to synthetic hidden inputs but outputs all-zero logits for real BPU `seg26` hidden states.

Unsafe claims:

- “Dream7B is accurately deployed on S100P.”
- “Dream7B is mathematically falsified against BF16.”
- “All diffusion models cannot run on S100P.”
- “Generation quality failed.” It was not run.
- “Product route failed.” It was not enabled; it remains pending/blocked.

## Issues to fix in the next package

1. **Include raw evidence subset.** At minimum include raw/dequant `.npy` for: one full-chain BPU case, one GGUF last-logits case, `seg26` output, isolated `seg27_28` synthetic input, and isolated `real_bpu_seg26_output`.
2. **Normalize zip paths.** Use POSIX `/` separators in zip arcnames.
3. **Fix final report field reference.** It cites `evidence/bf16_reference_probe/bf16_reference_export.json` field `status`, but the actual field is `verdict`.
4. **Improve gate packet builder.** `tools/build_dream7b_s100p_gate_packet.py` hard-codes `bf16_reference_status = unavailable` and only emits C/D verdicts. It must be updated before a real BF16 pass/fail run.
5. **Do not over-label `seg27_28` as dead.** Synthetic hidden inputs produce nonconstant logits; the real-chain hidden input causes zero logits. The sharper hypothesis is input-contract/range/layout/runtime handling at the `seg26_27 -> seg27_28` boundary.
6. **Boundary dump needs process isolation.** HBRT memory allocation failed when continuing to the next case. Run one case/segment chain per fresh process or add explicit runtime unload if supported.
