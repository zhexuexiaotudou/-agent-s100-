# Harness Default Service Contract

Stage 5 integrates Workspace Harness into the default OpenClaw NAS service path as policy middleware. The service is policy-first: OpenClaw presents the product surface, Qwen may advise, but every real tool execution must pass deterministic policy and the allowlisted dispatcher.

## Enabled By Default

- Readonly NAS search, folder summary, document RAG, report generation, audit trace, and token budget routing.
- Guarded single-file copy through `preview -> dry-run -> confirm -> execute`.
- Copy rollback for the target created by the same approved action.
- Privacy redaction before any cloud route decision.

## Copy Execution Requirements

Copy execute is available only when all of these are true:

1. The source and target are relative Personal paths accepted by `copy_route_guard`.
2. The user has seen preview and dry-run output.
3. The user types the approval phrase generated by the confirm route.
4. The signed approval token is fresh, action-bound, and matches the source and target hashes.
5. The source is rehashed immediately before execution.
6. The target is absent and overwrite is disabled.
7. Execution goes through `ai_nas_allowlisted_tool.sh ai_nas_action_execute_copy`.
8. A rollback manifest is written.

## Still Forbidden

- delete
- move
- rename
- chmod/chown
- overwrite
- recursive copy
- arbitrary shell
- unattended background writes
- Qwen autonomous tool execution
- Qwen choosing source/target and executing
- cloud private raw-content egress

## Service Boundary

The default service does not expose whole-NAS write authority. The Stage 5 smoke test uses a Codex-created synthetic source under `Collections/CodexPreflight/stage5_default_service/source/`; this evidence must not be described as arbitrary user-file copy support.
